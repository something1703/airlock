# 07 — Evaluation: proving Airlock works

Judges will see many "privacy" apps that simply claim to be private. Airlock **measures** it, publishes the misses, and shows each layer's contribution. This doc defines the harness, data, metrics and report.

---

## 1. Questions we answer

1. **Leakage:** how often does an identifying detail leave the phone?
2. **Re-identification:** given only what left, can a strong model guess who the writer is?
3. **Usefulness:** how much worse (or not) are answers compared with sending raw text?
4. **Fidelity:** are placeholders restored correctly?
5. **Cost and speed:** how long does sealing take on device, and how much work stays on the phone?
6. **Which layers matter:** rules vs. Apple's model vs. red-team.

## 2. Harness

```
AirlockBench (macOS app, uses AirlockKit + Firebase AI Logic)
  ├── Generate  → synthetic documents via synth.v1 (cloud) → datasets/synth-v1.jsonl
  ├── Run       → for each item, for each config:
  │                 RawText → SealPipeline (real on-device model) → SealedText (egress)
  │                 egress  → DeepAnswer (cloud)  → restored answer
  │                 raw     → DeepAnswer (cloud)  → baseline answer   (synthetic data only)
  │                 egress  → attacker.v1 (cloud, strongest model)
  │                 (answers) → judge.v1 (cloud)
  │               → runs/{runId}/items.jsonl  (upload to GCS)
  └── Report    → triggers Cloud Run Job airlock-scorer → BigQuery + reports/{runId}.md
```

Why a Mac app and not CI: Apple's on-device model only runs on Apple hardware with Apple Intelligence on. The Mac app uses **exactly the same AirlockKit code** as the iPhone app, so results describe the shipped pipeline.

Run modes:
- `--smoke` 30 items, one config (≈ 10 min) — used for the Day-3 go/no-go.
- `--full` all items × all configs (overnight).
- `--resume` continues an interrupted run.

Every run records: git SHA, prompt ids, Remote Config snapshot, dial, model names, macOS version, Mac chip.

## 3. Datasets

| Set | Source | Size | Use |
|-----|--------|------|-----|
| `synth-v1` | Generated by `synth.v1` (fictional people only), 10 doc types × 3 languages × 3 lengths, with gold spans, quasi-identifiers, profile | 600 | Main benchmark (leak, re-ID, quality, fidelity) |
| `synth-hard` | Same generator, `quasi_count` 3–5, small towns, rare jobs | 120 | Red-team value |
| `patterns-golden` | Hand-written strings for every pattern detector, with near-misses | 400 lines | Unit tests (deterministic) |
| `pupa-subset` | PUPA benchmark from the PAPILLON paper (real user queries with PII) | 200 | External comparison with PAPILLON's published 85.5% quality / 7.5% leakage |
| `demo-set` | The 5 scenarios in the video | 5 | Regression: these must always pass |

Rules:
- Synthetic data only for any step that sends **raw** text to the cloud (baseline answers, judge). Never run raw PUPA text through the cloud baseline beyond what the published paper already did — 👤 check PUPA's licence and terms before downloading; if unclear, skip it and say so in the README.
- Validate generated docs: every gold span is an exact substring; drop invalid items; log the drop rate.
- Hold out 20% of `synth-v1` (`synth-v1-test`) — prompt tuning only uses the other 80%. Report on the test split.

## 4. Metrics

| Metric | Definition | Target |
|--------|-----------|--------|
| **Doc leak rate** | % of docs where ≥1 gold direct identifier (PERSON, ORG name, LOCATION address/city, CONTACT, ID, SECRET, DOB) appears in egress text. Match: case-insensitive, diacritic-insensitive, also first/last-name tokens ≥ 3 chars for PERSON | ≤ 5% |
| **Span recall** (per category) | gold spans sealed or generalised / gold spans | ≥ 97% direct IDs |
| **Over-redaction** | sealed spans not in gold and not quasi / sealed spans | ≤ 15% |
| **Quasi coverage** | quasi-identifier spans generalised / quasi spans | report (red-team value) |
| **Re-ID success** | attacker guess matches profile, per attribute: name (exact token), city (exact or same metro), employer (fuzzy ≥ 0.8), occupation (judge-equivalent), age (±3 years). Report each + "≥2 attributes" | name ≤ 2%, ≥2 attrs ≤ 10% |
| **SDP findings** | Sensitive Data Protection `inspect` findings on egress (POSSIBLE+), excluding placeholders | median 0 |
| **Quality** | `judge.v1` win+tie rate of Airlock vs raw-to-cloud; mean `b_quality` | ≥ 85% win+tie |
| **Restore fidelity** | answers with all placeholders resolved and no unknown ids | ≥ 99% |
| **Model name leak** | answers containing a real gold name not introduced by restore (model guessed it) | 0 |
| **Seal latency** | p50/p95 ms per 100 words on device | p50 ≤ 1.3 s/100 words |
| **On-device share** | % of quick tasks where `modelVersion` is on-device | ≥ 70% |

Confidence intervals: Wilson 95% for rates; bootstrap (1,000 resamples) for means. Show CIs in the report and on the Evidence screen ("4.2% (2.9–6.0%)").

## 5. Configurations (ablations)

| Config | Layers |
|--------|--------|
| `A_raw` | Nothing sealed (baseline for quality; leak = 100% by definition) |
| `B_rules` | D1 vault (empty for synthetic) + D2 patterns |
| `C_rules_nl` | B + D3 NaturalLanguage tagger |
| `D_llm` | C + D4 Apple on-device detector |
| `E_redteam` | D + red-team auto-apply (Strict behaviour) |
| `F_vault` | E + vault seeded with the synthetic profile's name/city/employer (simulates a set-up user) |
| `G_naive_redact` | D but with `[REDACTED]` instead of placeholders + legend (shows why role hints matter for quality) |

Each run reports all metrics for every config. The headline numbers are `E_redteam` (out of the box) and `F_vault` (after onboarding).

## 7. Scorer (Cloud Run Job, `eval/scorer/`)

- Python 3.12, `google-cloud-dlp`, `google-cloud-bigquery`, `google-cloud-storage`.
- Input: `gs://…/runs/{runId}/items.jsonl`.
- Steps: compute deterministic metrics (leak, recall, fidelity) → SDP inspect each egress text (batch, rate-limited) → aggregate with CIs → write BigQuery → render Markdown + `evidence.json` → upload to `reports/`.
- Unit tests for metric functions with tiny fixtures (`eval/scorer/tests/`).
- Invocation: `gcloud run jobs execute airlock-scorer --args=--run-id=…`.

## 8. Human evaluation (small, real)

5 people, 20 minutes each, their own (or realistic) private text:
1. Paste something private; think aloud through Review.
2. Rate: "I understood what would be sent" (1–5), "I trusted it" (1–5), "The answer was useful" (1–5).
3. One open question: "What would make you trust it more?"

Record consented quotes for the Devpost story. No real user data is ever stored by the team: participants use the app on the team's Mac; raw captures are deleted after each session (Settings → Delete everything), and that deletion is shown on camera.
